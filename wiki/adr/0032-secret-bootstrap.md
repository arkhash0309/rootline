# 0032 — Secret bootstrap for repository credentials, database passwords and Anthropic keys

Status: accepted
Date: 2026-11-26
Label: spec-gap
Plan gap: PG-9, PG-10, PG-13 (`docs/superpowers/plans/2026-11-26-rootline-00-overview.md` §5)

## Context

PG-9 (spec reference SEC-100, SEC-082): ArgoCD needs repository credentials before it can deploy External Secrets Operator, so ESO cannot deliver `deploy-key-*`.

PG-10 (spec reference DB-002, SEC-100): CNPG managed roles reference existing password Secrets; they do not generate them. Services in `rootline` and `keycloak` need the same passwords.

PG-13 (spec reference SEC-100): The host-side eval runner and the in-cluster agent need different Anthropic keys (budget keys `dev`/`eval` vs `cluster`), but SEC-100 names only `ANTHROPIC_API_KEY`.

The spec does not answer these questions, so spec §0.3 applies: the simplest, cheapest and safest option is chosen. Each question is a row of the spec gap log in spec §26.

## Decision

PG-9: `task secrets:local` (local, ci) and `task gke:up` (gke) create the two ArgoCD repository Secrets in `argocd` directly with `kubectl`, labelled `argocd.argoproj.io/secret-type: repository`. All other secrets still come from ESO.

PG-10: ESO `Password` generators create `rootline-data/pg-<role>` (type `kubernetes.io/basic-auth`). ClusterSecretStore `pg-roles` (Kubernetes provider, remote namespace `rootline-data`) feeds ExternalSecrets `pg-<role>` in `rootline` and `keycloak`.

PG-13: `.env.local` key `ANTHROPIC_API_KEY` is the in-cluster key (`rootline-cluster`). The host uses `ROOTLINE_HOST_ANTHROPIC_API_KEY` (`rootline-dev`). CI uses repository secret `ANTHROPIC_API_KEY_CI`.

## Consequences

- `task secrets:local` and `task gke:up` create the two ArgoCD repository Secrets directly with `kubectl`; every other secret comes from External Secrets.
- Database passwords are generated by External Secrets `Password` generators and distributed through ClusterSecretStore `pg-roles`.
- The in-cluster key is `ANTHROPIC_API_KEY`, the host key is `ROOTLINE_HOST_ANTHROPIC_API_KEY` and CI uses `ANTHROPIC_API_KEY_CI`.

## Alternatives considered

- Sealed Secrets: not chosen because creating the Secrets directly from the task is simpler (spec §0.3).
- External Secrets Operator for repository credentials: not chosen because ArgoCD needs those credentials before it can deploy the operator (PG-9).
